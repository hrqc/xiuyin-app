# 琴房实录验收矩阵 room-recording-1

执行前固定；本轮验收对象为已留档 v0.2.0 / dbe1a852d2609126f1688039110ec0187808af63，并保留完整回归。新增测试工具不等于新增钢琴识别功能。测试输入为用户明确授权的谱子和视频目录，逐文件记录 SHA256，原件不改、不上传、不进 Git。

| 项目 | 固定通过条件 | 证据与边界 |
| --- | --- | --- |
| 原件完整性 | 测试前后来源 SHA256 相同 | 用户声称琴房实录；不猜测拍摄手机/距离/踏板条件 |
| 视频音轨读取 | 实际 Android MediaExtractor/MediaCodec 解码到 EOS，音轨时长/实际采样时长相差不超过 0.15 秒，非零有效帧，无未处理异常 | 音视频已录制后的离线回放，不冒充 AudioRecord 或现场麦克风 |
| 现有起音模块回放 | PCM16、采样率/声道取实际输出，1024采样帧、末帧按实际长度，完整经过生产 OnsetAnalyzer；时间来自媒体时间/采样数，不能用解码速度计时 | 记录全部帧、起音/延音/不确定状态、电平、削波及实际计算耗时；起音不等于音符或击键真值 |
| JPEG 识谱核心 | 两张实际 JPG 可由真实 OMR 产生结构化谱，并能校对音高/时值/小节/声部 | 当前能力缺失时必须判该核心项失败；“正确拒绝不支持格式”只算错误处理通过 |
| 演奏识别核心 | 实录实际进入已接入的音高/多音模块并产出与音频相关的音符证据 | 模块缺失为失败，不能把空音符/恒定 UNCERTAIN 当识别通过 |
| 跟谱与判错核心 | 同一结构化谱、真实音符事件驱动位置与纠错，停顿不假走、错音可恢复 | 模块缺失为失败；不能靠固定动画或手写该视频答案通过 |
| 准确率/误停率/定位/端到端延迟 | 有逐音人工真值、对齐参考及明确设备条件后才能计量 | 本轮缺少人工标注与现场手机；必须未验证/null，不填写0或虚构百分比 |
| UI 与错误恢复 | 真实系统选择器导入两张图，失败提示清楚、不崩溃、不破坏现有曲库，返回/重试/监控可用 | 实际截图、UI XML、App日志与SQLite/来源前后清单 |
| 原版本回归 | check.cmd 所有既有必需任务执行成功，原124项零失败/跳过，严格Lint/双构建/实际回退 | 回归通过与琴房核心验收分开记录 |
| 录音临时副本 | 仅固定测试缓存，完成/失败后删除，校验清理结果；不保存新原始PCM | JSON/CSV仅含指标，不含录音数据，用户原视频继续保留 |

核心验收汇总只有 JPEG OMR、演奏识别、跟谱纠错全部达到上述条件才可通过。解码、起音包络或124项既有回归通过不能使核心汇总变绿。失败不新建稳定Tag、不合入main，也不把基础版APK当完整陪练交付。

测试工具使用 Android 官方 MediaExtractor/MediaCodec/Instrumentation API，不下载模型或引入第三方服务。文档：
- https://developer.android.com/reference/android/media/MediaCodec
- https://developer.android.com/reference/android/app/Instrumentation
