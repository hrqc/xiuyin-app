## 本轮闭环

系统本地文件选择器 → 有界读取 → MusicXML安全解析 → 音高/精确拍时/和弦/谱表/声部/拍调谱号 → 时值和结构疑点 → 元数据预检 → 原XML按SHA256本地保存 → 独立元数据库登记UUID与来源信息 → 无原名时命名或跳过 → 我的乐谱搜索/标签/排序/收藏 → 数字事件视图 → 新实例/重启再次打开。当前是只读数据校对视图，完整五线谱排版/简谱/移调/试听/手动修改尚未接入。

常见含DTD头的XML当前明确拒绝，需无DTD的UTF-8未压缩导出。MXL、MIDI、图像、PDF、timewise、复杂反复/装饰/移调乐器等超出解析支持范围时明确提示；不能声称MusicXML全集兼容。按原始pitch/alter解析，不根据界面猜音。

新来源位于App私有files/digital-scores/，新命名库为独立score_metadata.db schema1；旧xiuyin.db schema1、recent_piece和practice_preparation不改变。正常导入/迁移不删除用户来源；只有明确确认删除才移除对应源文件，先持久写墓碑防止自动复活，删除失败保留状态并可重试。主动重新导入相同字节文件恢复同一UUID和既有命名。回退v0.1.1继续使用原功能；恢复v0.2.0重新读出保留的来源及命名。源文件最多2MiB/份、100份、总计100MiB；读取有15秒时限和两个占用槽位。源文件完整写入后在持久零字节.archive.lock保护下原子移动发布；异常文件和遗留临时文件显式可见。

## 小版本顺序

1. v0.2.0：当前结构化导入、可靠数字数据基础，以及本轮追加的无名称乐谱命名与本地查找闭环。
2. 后续v0.2.x：真实谱面消费者、基础编辑及状态一致性，按PRODUCT对应目标逐项验收。
3. 依最高优先级推进真实本地OMR输入分类/高清裁切/模型；再做Validation、二次识别、原图修谱与用户修改保护。
4. 与可信音频模型结合建立乐谱约束、多帧确认、跟谱及Confirmed Wrong，随后逐项扩展踏板/校准与误停验收。
5. Ring Buffer/短音频案例作为独立诊断小版；最后有界自适应并做长期回归，不在线训练主模型。

音符编辑与命名编辑不同：本轮只能编辑元数据，不改变音符、DigitalScore.title或源文件。临时名不能充当真实曲名，未知作者/页数不猜测；打开谱不计为练习。本轮已编写命名、搜索、数据库重开、删除防复活等测试，是否实际通过以最终报告为准。

具体检测承诺见TEST_MATRIX_SCORE1.md；最终报告、产物和发布状态在outputs/releases/v0.2.0/release-manifest.json，未生成时不得宣称已交付。
