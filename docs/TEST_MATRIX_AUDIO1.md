# V0.1.1 音频增量第一版验收矩阵

需求来源：修音_手机麦克风高精度识别_增量需求.md 第19节第一版。测试集 audio-foundation-1；V0.1 foundation-1 的曲库、静态谱、保存设置、数据库、日志回归全部保留。

本版范围在实现前固定：在现有 App 中加入内置麦克风采集、RMS 包络起音证据、多帧确认与 UNCERTAIN 的基础管线。用户主动点击才申请权限；不保存或上传 PCM。音符数组接口从一开始支持多音，但本版没有音高模型，不输出虚构音符或正确/错误结论。手机琴房效果标为实验中、未实测。

| 必需项 | 验证及通过阈值 |
| --- | --- |
| 构建与静态检查 | Debug/Release 编译成功；Kotlin warning-as-error、严格 Android Lint；零检测失败/跳过 |
| 原功能回归 | 保留原16项测试的等效行为断言；仅因新增明确授权的RECORD_AUDIO调整权限边界，网络与相机仍禁止 |
| Onset 纯算法 | 合成PCM明确标TEST DATA；静音无起音；单次持续音只计一次；间隔足够的重复起音分别计数；短瞬态须多帧确认；削波不作可信起音；错误输入明确拒绝 |
| 固定参数 | 采样率48000Hz、每帧1024采样；预热至少300ms；至少2帧确认；refractory至少80ms；候选电平高于噪声底12dB且不低于−50dBFS；静音阈值max(噪声底+6dB,−65dBFS)；证据分不作为音符准确率；帧间断流超过max(100ms,4×帧时长)则丢弃候选并重新预热 |
| 音频资源 | 显式开始、幂等停止/关闭、停止后不再增加帧数；重复开始不能创建多个录音器；退后台/离开音频页面停止并释放；再次开始可重新创建 |
| 权限/错误 | 无权限时拒绝采集并显示原因；初始化失败、读取错误、设备选路失败/改变不得继续显示正常；29+系统静音可被检测；无设备提示不可用 |
| 真实平台管线 | 现有Android15模拟器执行实际AudioRecord仪器测试（允许虚拟输入为静音）；至少取得有效PCM帧后才显示监听中；不启用宿主麦克风，不等同手机琴房实测 |
| 界面/监控 | 开始/停止控制、拒绝权限提示、音量/起音证据、UNCERTAIN、未实现音符识别边界可见；原日志控件保留；电平与状态只来自引擎 |
| 版本/回退 | 最终APK构建SHA与报告SHA一致；固定调试签名；数据库schema仍为1；模拟器更新到候选→安装v0.1.0已留档包→启动和检查原配置→重新安装候选，保留真实证据 |

音频处理耗时测量工作线程的实际计算时间，不能拿缓冲时长当设备端到端延迟。Audio Latency、识别准确率、误停率、跟谱恢复时间没有实测则为未测/不适用，不能填0表示优秀。

物理手机、真实钢琴、多音、踏板、校准、正式错误锁定/强化计数均不是本版已验证能力。正式琴房高精度验收须另行按 REAL_DEVICE_TESTS.md 采集人工真值，不能用合成PCM或模拟器静音替代。
